## 2026-11-20 — 历史加载与消息导航循环修复

- 计划：[HISTORY-NAV-OSCILLATION-2026-11-20](../plans/2026-11-20-history-navigation-oscillation.md)
- 变更：
  - 用户脚本加入当前 `turnListApi.scrollToKey` 主路径，同时保留旧 `ref.scrollToMessage` 和 DOM 有界搜索作为回退。
  - 用户消息 ID 可从外层 `...:user` 单元解析，覆盖内层气泡没有直接 ID 的新 DOM 结构。
  - 原生定位成功后设置 `nativeScrollOwned`；前台校正只观察目标，不再同时写 `scrollTop` 或扩展 padding。
  - 目标被虚拟列表回收时，经由串行化的原生 locator 恢复；原生请求未完成时抑制重复恢复。
  - 扩展滚动范围时保留第一次 baseline，并在容器或外部 padding 所有权变化时正确恢复。
- 偏差与原因：
  - `measureTurnBeforePaint + 二次 scrollToKey` 实验被放弃。实测仍产生 27 次原生滚动写入、42～44 次脚本写入，并出现约 `647px` padding，未解决循环。
  - 没有直接替换为 `backend-api/conversations/...` HTTP 请求；原生 loader 继续负责分页、缓存和分支状态。
- 验证：

  - `node --test` — 164 passed，0 failed，0 skipped，2026-11-20。
  - `git diff --check` — 通过，2026-11-20。
  - Windows Edge，完整历史加载后点击最后一条再点击倒数第二条：连续 8 秒可见运行，目标行保持挂载，稳定为 `height=31781`、`top=22499`、`y=9.3px`，padding 为空，横条保持高亮。
  - Windows Edge 历史按钮实测加载 1 页后完成并自动隐藏，原动态 `loadPrevious` 路径仍有效。
